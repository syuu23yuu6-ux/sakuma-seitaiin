# TDD (Test-Driven Development) フロー

本プロジェクトでは、TDD（テスト駆動開発）の基本原則である **Red -> Green -> Refactor** のサイクルに従って、品質と堅牢性の高いフロントエンド開発プロセスを実施します。

## 1. 原則 (The TDD Cycle)
フロントエンド（Vanilla JS / CSS / HTML）での実装においても以下のサイクルを厳守します。

1. **Red (テスト作成)**: 実装しようとするコンポーネントや関数のテストを先に書き、それが失敗することを確認する。
2. **Green (実装)**: テストをパスさせるための最小限のコード（HTML/CSS/JS）を書く。
3. **Refactor (リファクタリング)**: テストがパスする状態を維持したまま、コードをきれいにし、設計（Open Propsやモジュラー設計）を適用・最適化する。

## 2. フロントエンドにおけるテスト戦略

本プロジェクトはVanilla HTML/CSS/JSで構成されるため、以下の層でテストを定義します。

### A. 単体テスト (Unit Testing) - ロジック層
対象: `script.js` 内のビジネスロジックやデータ変換関数、UIハンドラーの純粋な関数部分。
アプローチ: 
- 関数を作成する前に期待する入出力を定義。
- JSの機能として正しい値が返却されるかを検証。
*(※モジュール化された関数に対して実施)*

### B. DOM/統合テスト (DOM/Integration Testing) - UI層
対象: アコーディオンやタブ、セクションの表示切り替え、フォームのバリデーションなど。
アプローチ:
- 特定のイベント（クリックやスクロール）を発火した際、期待するDOM要素が変化するか（クラスの付与、スタイルの変更等）を定義。
- HTMLのモックに対してテストを実行してから、実際の `index.html` に組み込む。

### C. ビジュアル・アクセシビリティ確認 - ビュー層
対象: CSS `style.css` のレイアウト、AOSやGSAPのアニメーション、およびレスポンシブ性。
アプローチ:
- 検証ツール（またはPlaywright等のE2E手法）によるPC/スマホのレンダリング確認。
- 各セクション構築時に、あらかじめ「この要素が画面内に入ったときにアニメーションが付与されるべき」という仕様を明文化してからスタイルを適用する。

## 3. TDD 実践のステップ (本プロジェクト向け)

各セクション（例: FAQセクション）を実装する際の標準ステップ：

1. **要件定義 (Spec)**: 対象セクションに必要なHTMLの要素（クラス名、役割）と、期待するJSの振る舞い（開閉アニメーションなど）を定義する。
2. **Red段階**: 実装が存在しない状態で、その機能が動かない（またはテストスクリプトがFailする）ことを確認する。
3. **HTML/CSS 実装**: 最小限のマークアップと、Open Propsを用いたスタイリングを行う。
4. **JavaScript 実装**: 期待されるインタラクションを満たすためのコードを書く。
5. **Green段階**: 手動およびテストコードによって正常に機能・アニメーションすることを確認する。
6. **Refactor**: `@layer`に違反していないか、冗長なコードがないか確認しリファクタリング。

## 4. 指示
エージェントは以降のすべての実装フェーズにおいて、コードをいきなり生成するのではなく、「まずどのようなテスト・仕様を満たすべきか」を提示（Redの確認）したうえで実装（Green）に移ること。
